# Orbit for macOS

A native AppKit host over the shared Rust crates. It is one process with no web runtime and no helper. Tested on macOS 27.2 on an Apple M4 Pro. The package declares macOS 14 as its minimum, but nothing older than 27.2 has been run.

## Build

You need Rust and the Command Line Tools. Xcode isn't needed.

```sh
scripts/macos/build_app.sh
```

This builds `crates/orbit-ffi` as a static library, builds the Swift package, and writes an ad-hoc-signed `platforms/macos/build/Orbit.app` with `LSUIElement` set and an icon from `assets/icon.svg`.

To build by hand, run `cargo build --release -p orbit-ffi` first, because the Swift package links its output. Then run `swift build -c release` in this folder.

Some Command Line Tools installs keep stale Swift 5.10 `*.private.swiftinterface` files in `usr/lib/swift/pm/ManifestAPI/PackageDescription.swiftmodule`. On those machines `swift build` fails for every package with an `Undefined symbols` link error on `Package.__allocating_init`. `build_app.sh` detects this and uses a cleaned copy under `.build`. Reinstalling the Command Line Tools fixes it for plain `swift build`.

## Run

```sh
open platforms/macos/build/Orbit.app
```

| Flag | Meaning |
|---|---|
| `--data-dir DIR` | Where Orbit stores everything. Default `~/Library/Application Support/Orbit` |
| `--hotkey CHORD` | Launcher shortcut for this run, with no fallback if it's taken |
| `--bench-log CSV` | Write timing lines in the same format as `platforms/windows/src/metrics.rs`. Timestamps are `mach_absolute_time` ticks. Also turns on the benchmark's Darwin notifications |
| `--no-reindex`, `--no-trim`, `--trim-ms N` | Skip the start-up scan of a stale index, or change when freed heap goes back to the system |
| `--wait-pid PID` | Wait for that process to end before starting. Restart uses this |
| `--index-apps` | Scan apps, write `apps.json` and exit |
| `--self-test` | Host checks that open no window and change nothing. See below |
| `--export-dir`, `--pasteboard`, `--app-dir`, `--fallback-hotkeys`, `--hidutil-matching`, `--no-open` | Test seams that keep test runs away from real folders, the real clipboard, real shortcuts and the browser. With `--no-open`, a link is reported but nothing opens |

The launcher shortcut is your chosen one, then Option+Space, Ctrl+Option+Space, Ctrl+Shift+Space and Ctrl+Option+O. Cmd+Space is never in that chain. If you choose it yourself, Orbit refuses while macOS has it enabled, and otherwise takes it with a visible notice. A failure shows in a toast, the menu bar menu, Settings and Diagnostics.

## Permissions

Nothing below is needed for the launcher, direct shortcuts, notes, snippets from the launcher (they fall back to the clipboard) or clipboard history.

| Feature | Grant |
|---|---|
| HyperKey Internal and Synthetic modes, trigger expansion | Accessibility and Input Monitoring |
| Typing snippets and pasting automatically | Accessibility |
| HyperKey External mode (another remapper makes the chord) | None. It uses `RegisterEventHotKey` |
| Empty Trash | Automation for Finder, which macOS asks about on first use |

Orbit reads these with `AXIsProcessTrusted` and `CGPreflight*`, which never prompt, and it won't call `CGEvent.tapCreate` without them, because that call makes macOS show its own dialog. Settings → HyperKey shows the state and has buttons for the two panes. Ad-hoc signing means each rebuild needs granting again.

Started from a terminal, macOS answers these checks for the terminal rather than Orbit. Settings and Diagnostics say so. Use `open` to see Orbit's own state.

## Caps Lock

Internal mode with Caps Lock uses `hidutil` to map Caps Lock to F18 and has the tap watch F18. Orbit writes a journal first, removes its pair on quit, at the lock screen and at the next start after a crash, and re-applies it after wake and unlock. The mapping dies at reboot anyway.

`hidutil --matching` has no filter for a single service, so a write reaches every keyboard. Orbit keeps other entries, and it refuses to act if another tool has already remapped Caps Lock or if keyboards hold different lists. If another tool maps Caps Lock to F20, choose F20 as the HyperKey.

## Clipboard

macOS has no copy notification, so while history is on and not paused Orbit reads `NSPasteboard.changeCount` every 0.75 s, slowing to every 3 s after 30 s with no change. With history off there is no timer. Copies marked `org.nspasteboard.ConcealedType`, `TransientType` or `AutoGeneratedType` are skipped before any body is read, as are excluded apps, matched by name or bundle ID. This is a best effort: an app that doesn't mark its copies can't be recognised.

macOS 15.4 added a per-app pasteboard access setting. If it's set to ask, each read can prompt, and if it's set to deny, history stays empty.

## Checks

```sh
cargo test -p orbit-ffi
platforms/macos/build/Orbit.app/Contents/MacOS/Orbit --self-test --data-dir /tmp/orbit-selftest
scripts/macos/feature_checks.sh /tmp/orbit-features
cargo run --release -p orbit-bench -- core data --out bench-results --name macos-core-data
cargo run --release -p orbit-bench -- e2e --orbit "$PWD/platforms/macos/build/Orbit.app/Contents/MacOS/Orbit" \
    --work-dir /tmp/orbit-e2e --opens 30 --idle-secs 60 --real-app Calculator:Calculator \
    --out bench-results --name macos-e2e
```

The e2e driver takes the keyboard for about a minute and a half. It injects keys only when the screen is unlocked, the process may post events, and its own window or Orbit holds the keyboard. It stops if anything else takes focus. With no grant or on a locked screen it runs the notification path and lists the key tests as not tested.

`bench-results/macos-baseline-*.json` are real runs of the final build. Compare with `--baseline FILE`. On identical code, a compare can still trip on timing noise. `data 10k: recent notes list` ranged from 2.9 to 14.3 ms in five runs here, so read which metric failed before treating a failure as a regression.

More detail is in `docs/fragments/macos-architecture.md`, `macos-shortcuts.md`, `macos-privacy.md` and `macos-data.md`.

## Known limitations

- Typing within about 15 ms of the shortcut can reach the previous app, because the key window changes after the hotkey arrives. Earlier runs lost 1 to 3 of 10 such attempts. The two runs of the final build lost none.
- Resident size is about 118 MB after idle, above the brief's figures, though footprint is about 30 MB. Most of the resident size is shared framework pages.
- The launcher draws on the CPU to avoid about 120 MB of graphics memory that AppKit's backing store allocated when rows changed. Which system component makes that allocation is not known. See `docs/fragments/macos-architecture.md`. Displays with another scale factor and the light theme are not tested with this draw path.
- LaunchServices opens a running app rather than a second copy, so `start:` behaves like `app:`.
- Lock Screen uses `SACLockScreenImmediate` from a private framework, because no public API exists, and falls back to `pmset displaysleepnow`.
